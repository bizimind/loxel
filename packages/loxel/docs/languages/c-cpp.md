# C and C++

C, C++ and Objective-C files are served by clangd. Shared language-server architecture: [LANGUAGE_SERVERS.md](../LANGUAGE_SERVERS.md).

## Manager

| Manager                                                         | Binary   | Args                                                                                                                                 | Scope    | Flags and config                                                                                                                 |
| --------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------- |
| [clangd-lsp-manager.ts](../../src/server/clangd-lsp-manager.ts) | `clangd` | `--resource-dir=<dir>` (bundled) `--limit-references=0 --rename-file-limit=0 --header-insertion-decorators=0 --query-driver=<globs>` | worktree | suppresses formatting and range formatting; untrusted: validates compile flags from project configuration before starting clangd |

[clangd-lsp-client.ts](../../src/lib/clangd-lsp-client.ts) binds the Monaco languages `c`, `cpp`, `objective-c` and `objective-cpp`, and shows the server's `window/showMessage` warnings. clangd ignores `languageId` and takes each file's language from its compile command.

## clangd

- **Binary.** On macOS, [download-clangd.ts](../../scripts/download-clangd.ts) ships the release's binary, thinned to the build machine's architecture and stripped, with its `lib/clang/<major>` minus the sanitizer runtimes as `clangd-resource`. A version upgrade changes no path, since the resource directory's name has no version in it. The manifest is limited to `darwin` with `platforms`, so other platforms build nothing for it. `resolveBinary` depends on [repository trust](../LANGUAGE_SERVERS.md#repository-trust). In a trusted repository it takes the login-shell `PATH`'s clangd, Xcode's included, if `checkClangd` passes it, and otherwise falls back as below; nothing is fetched in either mode. In an untrusted one `resolveBundledBinary("clangd")` looks for a sibling of the server, then the `PATH`, and Xcode's isn't taken, under any path. `checkClangd` reads `--version` from the filesystem root in both modes, and without the developer tools refuses `/usr/bin/clangd` on macOS without running it, since Apple's stub can raise the install dialog. `resolveBinary` returns null with a reason for `serverFailureReason`, which the start-failed path shows: what to install when none is found; that Xcode's clangd isn't supported; the minimum for a clangd older than 16, which would exit at once on the flags below; a version it can't read; and Windows, whose user config directory no environment variable selects (see Compile flags).
- **Trust.** `repoTrustRestriction` opts in to restarting on a change of trust. `reportsRestrictionAtStart` is off, since only `resolveBinary` knows whether anything is held back: it reports when the user has a clangd that would pass, saying the bundled one runs instead, or, with nothing bundled (Linux), that only system compilers are asked. With no usable clangd of the user's it reports nothing, so the UI doesn't ask. What trust changes is the binary, the `--query-driver` value and whether the Compile flags config applies; a trusted repository that falls back to the bundled binary still gets the last two.
- **Resource directory.** clangd finds the compiler's own headers, such as `stdarg.h`, relative to itself, and the bundled binary has no such tree beside it, so without one even C files fail to parse. `--resource-dir` points at `clangd-resource` when that directory is beside the bundled binary that resolved. A clangd from `PATH` keeps its own headers, which must match it. `share/` stays in the tree because clang's driver reports an error for `-fsanitize=cfi` without its ignorelist. An in-place update replaces the directory whole (`UPDATE_RESOURCE_DIRS` in [main.ts](../../src/electron/main.ts)).
- **Flags.** The defaults cap references at 1000 and renames at 50 files, which cuts results short on real projects, hence `--limit-references=0` and `--rename-file-limit=0`. `--header-insertion-decorators=0` keeps completion labels free of the marker clangd adds for an inserted include. The background index stays on (the default). `--compile-commands-dir` is deliberately absent: it applies to every file, while clangd's own search per file handles monorepos with several databases.
- **`--query-driver`.** clangd asks a compiler for its include paths when the path of the compiler a compile command names matches these globs, by running it. In a trusted repository the value is `**`, so that a cross-compiler or wrapper works under any name and in any location, the project included. Otherwise `queryDriverGlobs` lists only compiler names (`*gcc*`, `*g++*`, `*clang*`) in `/usr/bin`, `/usr/local/bin` and `/opt/homebrew/bin`, and never widens to a whole directory, `**` or anything inside a worktree.
- **Compile flags.** In a trusted repository clangd starts with the user's own `HOME` or `XDG_CONFIG_HOME` and reads their config itself, with none of what follows. Otherwise, compile flags that make the compiler write output files have no place in an editor session, and clangd takes flags from several places: compile databases, `compile_flags.txt`, `.clangd`, response files and compiler config files. `prepareClangdUserConfig` removes them where clangd combines those sources, in clangd's user config, which applies after every project's. Each spawn writes `<state dir>/clangd-config/.../clangd/config.yaml` and points clangd's process at it: `HOME` on macOS, `XDG_CONFIG_HOME` elsewhere, the variables clangd finds its user config directory through. Failing to write the file fails the start. The file holds `CompileFlags` with `Remove` and `Add`, then the user's own clangd config, as a later document, so a user's config that does not parse cannot affect the first one, and edits to it apply at the next start. Flags reached through `-Xclang` are listed by their frontend spelling, which makes clangd drop the `-Xclang` and any value with them; `-Xclang` itself stays because real builds use it (CMake's precompiled headers). `-Xpreprocessor`, `-Wp,` and `/clang:` are removed whole. Two flags on which clangd never finishes a file are removed too. The tests in [clangd-lsp-manager.test.ts](../../src/server/clangd-lsp-manager.test.ts) run real clangd over each source when one is on `PATH`.
- **Environment.** The redirected `HOME` on macOS, in an untrusted repository, only affects what clangd resolves through it: the user config, and the default module and global index caches, which end up under the state directory. The SDK comes from `xcrun`, which clangd runs at every start and which needs `/usr/bin` on `PATH`; the spawn's login-shell environment provides it, also when Loxel starts from Finder.
- **No developer tools.** `/usr/bin` holds Apple's stubs, which offer to install the developer tools when they are missing, and the bundled clangd, or one from Homebrew, runs on Macs without them. When `xcode-select -p` fails, clangd starts with `/usr/bin` removed from its `PATH` and from `--query-driver` (in a trusted repository, whose `**` would match it, a list of the top-level directories compilers live in replaces `**`), so it runs neither `xcrun` nor a stub compiler a compile database names, and the git check for the index directory (below) runs with the same `PATH`, with the background index off if that leaves no git. It then has no SDK, so standard headers are not found, and `onClientInitialized` sends a `window/showMessage` warning saying what to run. The check runs again at each start.
- **Formatting.** clangd advertises formatting, range formatting and on-type formatting. The first two are suppressed, since format on save owns formatting ([format-service.ts](../../src/server/format-service.ts) detects clang-format). The on-type provider stays registered and does nothing, as Loxel's editors do not enable `formatOnType`.
- **Completion.** Snippets stay on for argument placeholders. clangd escapes placeholders but writes names into snippets unescaped, so `escapeSnippetDollars` escapes a `$` that is neither one of its tabstops nor already escaped in completion results, which keeps `my$fn` from inserting a snippet variable. Includes for symbols from the index arrive as `additionalTextEdits`.
- **Semantic tokens.** On. clangd's legend includes `macro`, `modifier`, `operator`, `bracket`, `label`, `concept` and `unknown`, and `#if 0` regions arrive as `comment` tokens.
- **Index.** The background index is written to `.cache/clangd/index/` under the directory holding the compile database, with its own `.gitignore`, so it stays out of git status and the worktree watcher's change batches. Without a compile database clangd writes no index. `indexDirectoryIsSymlink` skips the background index (`--background-index=false`) when that directory or a parent up to `.cache` is a symlink, at the worktree's root or tracked by git at any depth, so index files aren't written outside the project tree. The check runs at each start and again when one of those paths changes (see Changes on disk).
- **Diagnostics and code actions.** Diagnostics are push only, `.clang-tidy` checks run inside clangd with no separate binary, and unused includes arrive tagged as unnecessary with a removal fix. Quick fixes come back only when the request echoes the diagnostic, which monaco-lsp-client does, as inline `edit.documentChanges`. Tweaks are commands (`clangd.applyTweak`) that reach the client back as `workspace/applyEdit`. clangd registers no file watchers.
- **Changes on disk.** clangd registers no file watchers, ignores `workspace/didChangeWatchedFiles`, and the client never sends `textDocument/didSave`, so `ClangdLspManager` overrides `notifyWatchedFilesChanged` and acts on changes itself instead of telling the server. `forwardWatchedFiles` and `watchedIgnoredGlobs` (`CLANGD_IGNORED_GLOBS`) are what bring the paths inside git-ignored directories, where compile databases and generated headers are, to that override. [clangd-file-changes.ts](../../src/server/clangd-file-changes.ts) classifies each path and owns one set of timers per session, which closing the session cancels; the manager tracks the session's open documents. Clangd's own index writes under `.cache/clangd/` and anything that is neither C-family nor configuration are dropped. Paths are recognized by name, so a header without an extension, or a directory moved or swapped whole (which reports only the directory), triggers nothing until another change does.

  | Change                                           | Trigger                                                                          | When                               | Why then                                                                                                                                                                             |
  | ------------------------------------------------ | -------------------------------------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
  | C-family source or header, open or not           | `didSave` of one open document, which makes clangd check them all                | 500 ms of quiet, at most 5 s       | A `git checkout` arrives in several batches                                                                                                                                          |
  | `compile_commands.json`, `compile_flags.txt`     | the same `didSave`, twice                                                        | 6 s and 31 s after the last change | clangd caches a file it found for 5 s and one it did not for 30 s, and a trigger inside the window is lost, so each change is covered for both rather than working out which applies |
  | `.clangd`, `.clang-tidy`                         | `didChange` with no `contentChanges` and `forceRebuild: true`, per open document | 6 s after the last change          | `didSave` does not re-run diagnostics when the compile command is unchanged, so a `.clang-tidy` or a `Diagnostics`-only `.clangd` needs a rebuild                                    |
  | `.cache`, `.cache/clangd`, `.cache/clangd/index` | `indexDirectoryIsSymlink` again, and on yes a restart                            | 100 ms and 3 s                     | The session respawns under the check its start makes; again at 3 s, since a `git checkout` updates git's index last                                                                  |
  | Source or header that is not open                | a restart                                                                        | 60 s of quiet                      | See below                                                                                                                                                                            |

  The rebuild carries the version the client last sent, which the manager tracks: without one clangd numbers the rebuild itself and stamps its quick fixes with a version the client does not have, and monaco-lsp-client refuses those. An unsaved open header is not seen by other open files; only what reaches the disk is.

- **Index freshness.** The index notices a disk edit to a file that is not open only when the file is opened or the index loads, and no trigger above reaches it. Loading compares every shard with its file's content and reindexes only what differs, so a restart (`LSP_RESTART_CLOSE_CODE`) brings it current: the load finished in under a second on fmt (33 commands) and curl (362), while the client reconnects and opens its documents again, whose preambles clangd then rebuilds, which is the larger cost on heavy C++. So only files that are not open count (the open file's text already reaches the index), it waits for 60 s of quiet so that a burst of edits costs one, and there is at most one per worktree every 5 minutes. With nothing open it stays pending for the next file opened. With the index off, or no `compile_commands.json` found from any open file, it does not happen.

# C and C++

C, C++ and Objective-C files are served by clangd. Shared language-server architecture: [LANGUAGE_SERVERS.md](../LANGUAGE_SERVERS.md).

## Manager

| Manager                                                         | Binary   | Args                                                                                                                                 | Scope    | Flags and config                                                                                                      |
| --------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------ | -------- | --------------------------------------------------------------------------------------------------------------------- |
| [clangd-lsp-manager.ts](../../src/server/clangd-lsp-manager.ts) | `clangd` | `--resource-dir=<dir>` (bundled) `--limit-references=0 --rename-file-limit=0 --header-insertion-decorators=0 --query-driver=<globs>` | worktree | suppresses formatting and range formatting; validates compile flags from project configuration before starting clangd |

[clangd-lsp-client.ts](../../src/lib/clangd-lsp-client.ts) binds the Monaco languages `c`, `cpp` and `objective-c`, and shows the server's `window/showMessage` warnings. clangd ignores `languageId` and takes each file's language from its compile command, so Objective-C++ (`.mm`, highlighted as `cpp`) needs no ID of its own.

## clangd

- **Binary.** On macOS, [download-clangd.ts](../../scripts/download-clangd.ts) ships the release's binary, thinned to the build machine's architecture and stripped, with its `lib/clang/<major>` minus the sanitizer runtimes as `clangd-resource`. A version upgrade changes no path, since the resource directory's name has no version in it. The manifest is limited to `darwin` with `platforms`, so other platforms build nothing for it. `resolveBundledBinary("clangd")` looks for a sibling of the server, then the login-shell `PATH`. `resolveBinary` returns null with a reason for `serverFailureReason`, which the start-failed path shows: what to run per platform when none is found, or for Apple's `/usr/bin/clangd` stub when `xcode-select -p` finds no developer tools, since running it would raise macOS's install dialog at every retry; the minimum for a clangd older than 16 (`checkClangd`), which would exit at once on the flags below; and on Windows, whose user config directory no environment variable selects (see Compile flags).
- **Resource directory.** clangd finds the compiler's own headers, such as `stdarg.h`, relative to itself, and the bundled binary has no such tree beside it, so without one even C files fail to parse. `--resource-dir` points at `clangd-resource` when that directory is beside the binary that resolved. A clangd from `PATH` keeps its own headers, which must match it. `share/` stays in the tree because clang's driver reports an error for `-fsanitize=cfi` without its ignorelist. An in-place update replaces the directory whole (`UPDATE_RESOURCE_DIRS` in [main.ts](../../src/electron/main.ts)).
- **Flags.** The defaults cap references at 1000 and renames at 50 files, which cuts results short on real projects, hence `--limit-references=0` and `--rename-file-limit=0`. `--header-insertion-decorators=0` keeps completion labels free of the marker clangd adds for an inserted include. The background index stays on (the default). `--compile-commands-dir` is deliberately absent: it applies to every file, while clangd's own search per file handles monorepos with several databases.
- **`--query-driver`.** clangd asks a compiler for its include paths when the path of the compiler a compile command names matches these globs, by running it. `queryDriverGlobs` lists only compiler names (`*gcc*`, `*g++*`, `*clang*`) in `/usr/bin`, `/usr/local/bin` and `/opt/homebrew/bin`. A glob covering a whole directory or using `**` would run other programs, so the list never widens to those or to anything inside a worktree.
- **Compile flags.** Compile flags that make the compiler write output files have no place in an editor session, and clangd takes flags from several places: compile databases, `compile_flags.txt`, `.clangd`, response files and compiler config files. `prepareClangdUserConfig` removes them where clangd combines those sources, in clangd's user config, which applies after every project's. Each spawn writes `<state dir>/clangd-config/.../clangd/config.yaml` and points clangd's process at it: `HOME` on macOS, `XDG_CONFIG_HOME` elsewhere, the variables clangd finds its user config directory through. Failing to write the file fails the start. The file holds `CompileFlags` with `Remove` and `Add`, then the user's own clangd config, as a later document, so a user's config that does not parse cannot affect the first one, and edits to it apply at the next start. The removal also covers the forwarders that pass flags on to the compiler (`-Xclang`, `-Xpreprocessor`, `-Wp,`, `/clang:`), so a project's `-Xclang` flags do not reach clangd, and `-traditional-cpp`, on which clangd never finishes a file. The tests in [clangd-lsp-manager.test.ts](../../src/server/clangd-lsp-manager.test.ts) run real clangd over each source when one is on `PATH`.
- **Environment.** The redirected `HOME` on macOS only affects what clangd resolves through it: the user config, and the default module and global index caches, which end up under the state directory. The SDK comes from `xcrun`, which clangd runs at every start and which needs `/usr/bin` on `PATH`; the spawn's login-shell environment provides it, also when Loxel starts from Finder.
- **No developer tools.** `/usr/bin` holds Apple's stubs, which offer to install the developer tools when they are missing, and the bundled clangd runs on Macs without them. When `xcode-select -p` fails, clangd starts with `/usr/bin` removed from its `PATH` and from `--query-driver`, so it runs neither `xcrun` nor a stub compiler a compile database names, and the git check for the index directory (below) runs with the same `PATH`, with the background index off if that leaves no git. It then has no SDK, so standard headers are not found, and `onClientInitialized` sends a `window/showMessage` warning saying what to run. The check runs again at each start.
- **Formatting.** clangd advertises formatting, range formatting and on-type formatting. The first two are suppressed, since format on save owns formatting ([format-service.ts](../../src/server/format-service.ts) detects clang-format). The on-type provider stays registered and does nothing, as Loxel's editors do not enable `formatOnType`.
- **Completion.** Snippets stay on for argument placeholders. clangd writes names into snippets unescaped, so `escapeSnippetDollars` escapes a `$` that is not one of its tabstops in completion results, which keeps `my$fn` from inserting a snippet variable. Includes for symbols from the index arrive as `additionalTextEdits`.
- **Semantic tokens.** On. clangd's legend includes `macro`, `modifier`, `operator`, `bracket`, `label`, `concept` and `unknown`, and `#if 0` regions arrive as `comment` tokens.
- **Index.** The background index is written to `.cache/clangd/index/` under the directory holding the compile database, with its own `.gitignore`, so it stays out of git status and the worktree watcher's change batches. Without a compile database clangd writes no index. `indexDirectoryIsSymlink` skips the background index (`--background-index=false`) when that directory or a parent up to `.cache` is a symlink, at the worktree's root or tracked by git at any depth, so index files aren't written outside the project tree.
- **Diagnostics and code actions.** Diagnostics are push only, `.clang-tidy` checks run inside clangd with no separate binary, and unused includes arrive tagged as unnecessary with a removal fix. Quick fixes come back only when the request echoes the diagnostic, which monaco-lsp-client does, as inline `edit.documentChanges`. Tweaks are commands (`clangd.applyTweak`) that reach the client back as `workspace/applyEdit`. clangd registers no file watchers.

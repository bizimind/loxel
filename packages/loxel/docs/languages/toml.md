# TOML

TOML files are served by Tombi, which gets its schemas from the map described in [Schemas and JSON validation](../LANGUAGE_SERVERS.md#schemas-and-json-validation). Shared language-server architecture: [LANGUAGE_SERVERS.md](../LANGUAGE_SERVERS.md).

## Tombi

[toml-lsp-manager.ts](../../src/server/toml-lsp-manager.ts) runs [Tombi](https://github.com/tombi-toml/tombi) per worktree. Tombi was chosen over Taplo (Even Better TOML's server) because it is actively released, supports current JSON Schema drafts, and serves pull diagnostics, code actions, go-to-definition and inlay hints besides completion, hover, symbols and folding; Taplo has not had a release since 0.10.0 (May 2025) and takes associations only as regular expressions.

- **Associations.** The schema map reaches Tombi as editor configuration, a `workspace/didChangeConfiguration` with a `tombi` section (`tombiSettings`), sent on `initialized` and on every `updateSchemas()`. Each Loxel glob becomes Tombi patterns (`toTombiPatterns`): brace alternatives are expanded, since Tombi's glob matcher has none, and a plain name (`pyproject.toml`, `.cargo/config.toml`) gets `**/` so it matches at any depth, as Monaco's JSON `fileMatch` does. Tombi matches against the canonical absolute path and its `*` also matches `/`, so a pattern with wildcards is anchored at the session's worktree instead (`config/*.toml` becomes `<worktree>/**/config/*.toml`), keeping it from matching through an ancestor directory; within the worktree a TOML glob's `*` still spans directories, which JSON's does not. Editor configuration replaces the previous one wholesale, so updates and removals apply live, unlike `tombi/associateSchema`, which only appends.
- **Catalogs and strict mode off.** The same configuration sets `schema.catalog.paths = []`, so neither SchemaStore's catalog nor Tombi's embedded one associates schemas: the Schemas settings are the only automatic associations, and disabling a built-in removes its schema. `schema.strict = false` keeps JSON Schema semantics (Tombi's strict mode treats a missing `additionalProperties` as `false`), so a schema validates TOML as it validates JSON and YAML. `#:schema` directives in a file take precedence over the configuration.
- **Offline.** Tombi never reaches the network: it reads remote schemas only from a cache that Loxel fills, see [Schemas](../LANGUAGE_SERVERS.md#schemas-and-json-validation). `TOMBI_SCHEMA_TRUSTED_HOSTS` lists the hosts of the user's chosen schemas (`SchemaConsent.chosenHosts`), since Tombi checks the host before it looks in its cache and refuses a non-public one unless it is listed. Offline also turns off what Tombi's Cargo and uv extensions fetch from package registries.
- **Tombi's own configuration wins.** Tombi uses editor configuration only for files that no Tombi config governs: a `tombi.toml` / `.tombi.toml` / `.config/tombi.toml` or a `pyproject.toml` with `[tool.tombi]` in the file's directory or above, or the user's `~/.config/tombi/config.toml`. Those projects keep the settings of the `tombi` CLI, while remote schemas and catalogs they name are not downloaded.
- **Diagnostics refresh.** Tombi caches each open document's diagnostics per version, and a configuration change does not clear the cache. After each push the manager therefore sends a `tombi/associateSchema` with no file patterns (it matches nothing), which resets the cache and makes Tombi send `workspace/diagnostic/refresh`, so Monaco pulls fresh diagnostics without an edit. Tombi takes that association only after the configuration is in place (it holds the association list's read lock until then), and keeps every association, so each push leaves one inert entry for the session's lifetime.
- **Flags.** Semantic tokens are off (the TextMate grammar highlights TOML), formatting is suppressed because format on save owns it and Tombi's formatter reorders keys by the schema's `x-tombi-table-keys-order`, and watched files are forwarded so Tombi reloads changed config files and local schemas.

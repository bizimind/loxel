# site

Static [Astro](https://astro.build) site for loxel at [bizimind.io](https://bizimind.io): landing page, download page, and the user docs.

## Layout

- `src/pages/` — `index.astro` (landing), `download.astro`, and `docs/[...slug].astro`, which renders the docs collection.
- `src/content/docs/` — user documentation as Markdown/MDX. Frontmatter: `title` (required), `description`, and `order` (sidebar position, default 99); schema in `src/content.config.ts`. Inline code that is a key combo (for example `` `Cmd+Shift+P` ``) renders as keyboard keys (`src/lib/satteri-kbd.ts`). Renaming a page changes its URL, so add the old path to `redirects` in `astro.config.mjs`.
- `src/lib/manifest.ts` — fetches the latest loxel release manifest (`https://loxel.bizimind.io/loxel/manifest.json`) at build time for the version and download links. Production builds fail if it is unreachable; `astro dev` falls back to a placeholder.
- `src/lib/analytics.ts` — PostHog analytics (see [Analytics](#analytics)).
- `functions/` — Cloudflare Pages Functions deployed with the site; `functions/ingest/` is the PostHog proxy.
- `public/screenshots/` — app screenshots generated by loxel's Playwright e2e suite (`pnpm -C packages/loxel run e2e`); do not edit by hand.

## Commands

```bash
pnpm -C packages/site run dev        # local dev server
pnpm -C packages/site run build      # static build into dist/
pnpm -C packages/site run preview    # serve the built site
pnpm -C packages/site run typecheck  # astro check
```

## Analytics

The site sends product analytics to PostHog (EU cloud) when it is built with `PUBLIC_POSTHOG_KEY` set to the PostHog project API key. Without the key, or under `astro dev`, nothing is loaded or sent. CI passes the key (the `PUBLIC_POSTHOG_KEY` Actions variable) only to production builds from `main`, so preview deployments track nothing. To test locally, build with the key and serve with `pnpm dlx wrangler pages dev dist` from this package, which also runs the `/ingest` proxy; `astro preview` has no Functions.

- **Proxy**: the SDK sends everything to `/ingest` on the site's own domain, and the `functions/ingest/[[path]].ts` Pages Function forwards it to PostHog with the visitor's IP, so blocklists that match PostHog's domains don't drop events.
- **Cookieless**: PostHog runs with `cookieless_mode: "always"` and stores nothing in the browser, which is designed to avoid needing a cookie consent banner. PostHog identifies a visitor by a daily-salted hash of IP and user agent, so funnels work across page loads within a day but visitors aren't recognized on later days. The PostHog project must have **Enable cookieless tracking** turned on (Settings > Project > Web analytics), or events are dropped.
- **Events**: pageviews and autocapture, plus the custom events in `src/lib/analytics.ts`: `download_clicked`, `github_link_clicked`, `cta_viewed`, `docs_nav_clicked`, and `docs_scroll_depth`. Markup opts in by spreading `trackClick`, `trackView`, or `trackScrollDepth` onto an element, which adds `data-analytics-*` attributes; don't attach tracking to copy or CSS selectors.

## Deployment

The `release-site.yml` workflow builds the site and deploys `dist/` and `functions/` to the `loxel` Cloudflare Pages project on every push that touches `packages/site/**`. It runs wrangler from this package, so `wrangler.toml` here is the deployment's config. Pushes to `main` go to production; other branches get a preview deployment whose URL is commented on the open PR, and `site-preview-cleanup.yml` deletes previews when the PR closes or the branch is deleted. The loxel release workflow also dispatches a rebuild so the download page picks up each new release.

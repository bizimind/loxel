# site

Static [Astro](https://astro.build) site for loxel at [bizimind.io](https://bizimind.io): landing page, download page, and the user docs.

## Layout

- `src/pages/` — `index.astro` (landing), `download.astro`, and `docs/[...slug].astro`, which renders the docs collection.
- `src/content/docs/` — user documentation as Markdown/MDX. Frontmatter: `title` (required), `description`, and `order` (sidebar position, default 99); schema in `src/content.config.ts`. Inline code that is a key combo (for example `` `Cmd+Shift+P` ``) renders as keyboard keys (`src/lib/satteri-kbd.ts`). Renaming a page changes its URL, so add the old path to `redirects` in `astro.config.mjs`; a section moved to another page goes in the old page's `movedAnchors` frontmatter (old anchor to new URL), which a small script on the page follows. `languages/` holds one page per language, which joins the sidebar by itself.
- `src/lib/site.ts` — site identity (name, GitHub URLs, theme color) and `pagePath()`, the page's public path: the build writes `docs/git.html` and serves it at `/docs/git`, so `Astro.url.pathname` ends in `.html` during the build. Link to pages without a trailing slash (`/docs/git`); the slash form redirects.
- `src/layouts/Base.astro` — the page head: canonical URL (always `https://bizimind.io`), Open Graph and Twitter tags, icons, and schema.org JSON-LD built in `src/lib/structured-data.ts` (site-wide Organization and WebSite, plus the app and its source repository on the landing page).
- `src/pages/robots.txt.ts`, `src/pages/apple-touch-icon.png.ts` — built-time endpoints: robots.txt pointing at the sitemap from `@astrojs/sitemap`, and the touch icon rendered from `public/favicon.svg`. `src/pages/404.astro` becomes `404.html`, which Cloudflare Pages serves for unknown paths.
- `public/_headers` — Cloudflare Pages headers; marks every `*.pages.dev` host `noindex` so only bizimind.io is indexed.
- `src/lib/manifest.ts` — fetches the latest loxel release manifest (`https://loxel.bizimind.io/loxel/manifest.json`) at build time for the version and download links. Production builds fail if it is unreachable; `astro dev` falls back to a placeholder.
- `src/lib/analytics.ts` — PostHog analytics (see [Analytics](#analytics)).
- `functions/` — Cloudflare Pages Functions deployed with the site; `functions/ingest/` is the PostHog proxy.
- `astro.config.mjs` `fonts` — Inter and JetBrains Mono, served from the site itself through Astro's Fonts API (files from the `@fontsource-variable` packages, Inter preloaded, size-adjusted fallbacks). Pages load no third-party assets; self-host anything new the same way. `public/_headers` gives the hashed files under `/_astro/` immutable caching on Cloudflare Pages.
- `public/screenshots/` — app screenshots generated by loxel's Playwright e2e suite (`pnpm -C packages/loxel run e2e`); do not edit by hand.

## Commands

```bash
pnpm -C packages/site run dev        # local dev server
pnpm -C packages/site run build      # static build into dist/
pnpm -C packages/site run preview    # serve the built site
pnpm -C packages/site run typecheck  # astro check
```

## Analytics

The site sends product analytics to PostHog (EU cloud) when it is built with `PUBLIC_POSTHOG_KEY` set to the PostHog project API key. Without the key, under `astro dev`, or for visitors whose browser sends Do Not Track or Global Privacy Control, nothing is loaded or sent. CI passes the key (the `PUBLIC_POSTHOG_KEY` Actions variable) only to production builds from `main`, so preview deployments track nothing. To test locally, build with the key and serve with `pnpm dlx wrangler pages dev dist` from this package, which also runs the `/ingest` proxy; `astro preview` has no Functions.

- **Proxy**: the SDK sends everything to `/ingest` on the site's own domain, and the `functions/ingest/[[path]].ts` Pages Function forwards it to PostHog with the visitor's IP, so blocklists that match PostHog's domains don't drop events.
- **Cookieless**: PostHog runs with `cookieless_mode: "always"` and stores nothing in the browser, which is designed to avoid needing a cookie consent banner. PostHog identifies a visitor by a daily-salted hash of IP and user agent, so funnels work across page loads within a day but visitors aren't recognized on later days. The PostHog project must have **Enable cookieless tracking** turned on (Settings > Project > Web analytics), or events are dropped.
- **Events**: pageviews and page leaves, plus the custom events in `src/lib/analytics.ts`: `download_clicked`, `github_link_clicked`, `cta_viewed`, `docs_nav_clicked`, `docs_scroll_depth`, and `page_not_found` (sent from the 404 page; its path and referrer show which links need a `redirects` entry). Markup opts in by spreading `trackClick`, `trackView`, `trackScrollDepth`, or `trackLoad` onto an element, which adds `data-analytics-*` attributes; don't attach tracking to copy or CSS selectors.

## Deployment

The `release-site.yml` workflow builds the site and deploys `dist/` and `functions/` to the `loxel` Cloudflare Pages project on every push that touches `packages/site/**`. It runs wrangler from this package, so `wrangler.toml` here is the deployment's config. Pushes to `main` go to production; other branches get a preview deployment whose URL is commented on the open PR, and `site-preview-cleanup.yml` deletes previews when the PR closes or the branch is deleted. The loxel release workflow also dispatches a rebuild so the download page picks up each new release.

# site

Static [Astro](https://astro.build) site for loxel at [bizimind.io](https://bizimind.io): landing page, download page, and the user docs.

## Layout

- `src/pages/` — `index.astro` (landing), `download.astro`, and `docs/[...slug].astro`, which renders the docs collection.
- `src/content/docs/` — user documentation as Markdown/MDX. Frontmatter: `title` (required), `description`, and `order` (sidebar position, default 99); schema in `src/content.config.ts`. Inline code that is a key combo (for example `` `Cmd+Shift+P` ``) renders as keyboard keys (`src/lib/satteri-kbd.ts`).
- `src/lib/manifest.ts` — fetches the latest loxel release manifest (`https://loxel.bizimind.io/loxel/manifest.json`) at build time for the version and download links. Production builds fail if it is unreachable; `astro dev` falls back to a placeholder.
- `public/screenshots/` — app screenshots generated by loxel's Playwright e2e suite (`pnpm -C packages/loxel run e2e`); do not edit by hand.

## Commands

```bash
pnpm -C packages/site run dev        # local dev server
pnpm -C packages/site run build      # static build into dist/
pnpm -C packages/site run preview    # serve the built site
pnpm -C packages/site run typecheck  # astro check
```

## Deployment

The `release-site.yml` workflow builds the site and deploys `dist/` to the `loxel` Cloudflare Pages project on every push that touches `packages/site/**`. Pushes to `main` go to production; other branches get a preview deployment whose URL is commented on the open PR, and `site-preview-cleanup.yml` deletes previews when the PR closes or the branch is deleted. The loxel release workflow also dispatches a rebuild so the download page picks up each new release.
